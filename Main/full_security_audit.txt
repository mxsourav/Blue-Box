CVE-BB-001: UNSIGNED FIRMWARE FLASHING FROM SD CARD
────────────────────────────────────────────────────
File:     flasher-tool-function.ino, lines 108-155
Code:
  void flashBinary(String path) {
    File updateBin = SD.open("/" + path);
    size_t updateSize = updateBin.size();
    Update.begin(updateSize);
    size_t written = Update.writeStream(updateBin);
    if (written == updateSize && Update.end(true)) {
      ESP.restart();
    }
  }
Impact:   ANY .bin file on SD card replaces device firmware. No signature,
          no checksum, no authentication. Brief physical access = persistent
          compromise. Update.end(true) forces acceptance.
Fix:      Add SHA-256 hash verification or Ed25519 signature check before
          calling Update.begin().

CVE-BB-002: ESP-IDF FRAME SANITY CHECK BYPASS
──────────────────────────────────────────────
File:     deauth_override.c, lines 3-5
Code:
  int ieee80211_raw_frame_sanity_check(int32_t arg, int32_t arg2, int32_t arg3) {
      return 1;
  }
Impact:   Overrides ALL ESP-IDF raw 802.11 frame validation. Any crafted
          frame (malformed, oversized, illegal) can be transmitted. Could
          crash the WiFi stack itself via self-injected malformed frames.
Fix:      Implement minimal validation (frame length checks, type checks)
          instead of blanket bypass.

CVE-BB-003: HID SCRIPT INFINITE RECURSION VIA REPEAT COMMAND
─────────────────────────────────────────────────────────────
File:     hid-script.ino, lines 159-169
Code:
  } else if (upperLine.startsWith("REPEAT ")) {
    int repeatCount = upperLine.substring(7).toInt();
    for (int i = 0; i < repeatCount; i++) {
      hidRunScript(path);  // RECURSIVE CALL!
    }
  }
Impact:   A .duck script with "REPEAT 999" causes unbounded recursion.
          Each call re-parses the file and hits REPEAT again = infinite
          recursion = GUARANTEED stack overflow crash.
Fix:      Replace recursion with iterative replay. Track last command and
          repeat it N times without re-calling hidRunScript().

CVE-BB-005: SELF-DEAUTH WITH NO TARGET VALIDATION
──────────────────────────────────────────────────

CVE-BB-010: PACKET COUNTER RACE CONDITION IN ISR
─────────────────────────────────────────────────
File:     packet-analyzer.ino, lines 23, 45, 211, 225
Code:
  // In ISR (IRAM_ATTR):
  sniffer.packetCounter++;
  // In main loop (not synchronized):
  uint16_t pktCount = sniffer.packetCounter;  // line 211
  // ... several lines later ...
  sniffer.packetCounter = 0;                   // line 225
Impact:   16-bit read is not atomic on ESP32. Counter can be read+cleared
          non-atomically = lost packet counts. Also uint16_t overflows
          at 65535 with no wrap handling.
Fix:      Use portENTER_CRITICAL/portEXIT_CRITICAL around read-and-clear.
